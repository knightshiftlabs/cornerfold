Check our claims

Every promise Cornerfold makes, how it is kept, how it is tested, and how you can check it yourself.

You shouldn’t have to take a privacy promise on trust. For each claim below, the first answer is what makes it true, the second is the automatic test that fails if it ever stops being true, and the third is how you can see for yourself. The tests run on every change to Cornerfold, and their results are public on GitHub.

Your files never leave your device

How it’s kept. Everything happens in your browser. Cornerfold’s code contains no way of sending data anywhere: no uploads, no requests, no beacons. As a second safeguard, the site’s security policy tells your browser to block connections to any other website.

How it’s tested. Cornerfold is tested in a real browser, under the site’s real security policy, adding, editing and exporting files with every tool. Every one of those tests fails if any request leaves the site. A separate test fails if the code ever contains a way of sending data.

Check it yourself. Open your browser’s developer tools, choose the Network tab, then add and export a file. You’ll see Cornerfold load its own files and nothing else.

No tracking, analytics or ads

How it’s kept. Cornerfold has no analytics or advertising code. Our hosting provider’s own analytics are switched off, and every page tells anything between us and you not to change it, so no one can add a script on the way.

How it’s tested. Every day, and after every change, an automatic check fetches the live site and fails if any page loads anything from another website.

Check it yourself. View the source of any page: every script and style comes from cornerfold.org.

The site runs exactly the public source code

How it’s kept. The source code is public on GitHub, and building it always gives the same files, byte for byte.

How it’s tested. The same daily check builds the code on GitHub and compares every file it makes with the file cornerfold.org actually serves. Any difference, added or changed, fails the check.

Check it yourself. With Node.js installed, download the code and run npm ci, npm run build and npm run check:live.

Passwords are never kept

How it’s kept. A password you type is used once, on your device, to open that file, and then forgotten.

How it’s tested. After opening a protected file, a browser test searches everywhere a website can store things (its storage, cookies, caches and the page itself) and fails if the password is found anywhere.

Check it yourself. Open a protected file, then look under your browser’s Application or Storage tab in the developer tools.

No accounts and no cookies

How it’s kept. There is nothing to sign in to, and Cornerfold sets no cookies.

How it’s tested. A browser test fails if the site sets any cookie.

Check it yourself. Look under Cookies in your browser’s developer tools: there are none for cornerfold.org.

Strict security settings

How it’s kept. The site sends strict security headers, which limit what a page may load and do, and forbid other sites from framing it.

How it’s tested. Every browser test runs under these exact headers, and the daily check fails if the live site sends anything different.

Check it yourself. Run cornerfold.org through an independent scanner such as securityheaders.com.

It works offline

How it’s kept. After your first visit, the app keeps a copy of its own files (never yours) in your browser.

How it’s tested. By hand, before releases. An automatic test is planned and not built yet.

Check it yourself. Visit once, switch on airplane mode, then reload the page and use it.

If any of this is ever untrue

That would be a serious bug. Please tell us at security@cornerfold.org.
